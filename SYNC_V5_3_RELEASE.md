# TSD v5.3.0 — безопасная фоновая синхронизация

## Изменения
- Менеджер sync.js обрабатывает **не более пяти сборок за цикл** и запускает следующий цикл с паузой 1,5 сек. Каждый POST остаётся отдельным запуском Apps Script.
- При онлайн-входе, возврате сети/фокуса и сохранении новой сборки цикл запускается автоматически. Активное сканирование не блокируется модальными окнами.
- Проверка SENDING / UNCERTAIN **только по jobId**; эти записи не отправляются повторно автоматически, если сервер не дал однозначного ответа.
- Успешные сборки остаются в IndexedDB со статусом SUCCESS; исходные ERROR/RESOLVED сохраняются.
- Очередь на главном экране ограничена отображением последних 40 записей, сами данные не ограничиваются.
- Встроенный механизм Web Locks предотвращает одновременную отправку двумя вкладками одного origin; для старых браузеров используется консервативная localStorage-блокировка.
- Имя IndexedDB `stockflow-tsd-v1`, версия 1 и объектные хранилища `meta`, `catalog`, `queue`, `draft` сохранены.
- Версия кэша Service Worker увеличена до 5.3.0. IndexedDB не очищается и не переименовывается.

## Важно
1. Перед выпуском на все ТСД **сделайте резервное копирование очереди** с каждого терминала средствами диагностики/экспорта. Нельзя сбрасывать данные сайта или переустанавливать PWA.
2. Сначала испытать на одном ТСД с несколькими тестовыми сборками и проверить строки в TSD_JOBS, MOVEMENTS, BALANCES, CHZ.
3. Принудительно закрытый PWA не гарантирует работу фоновой передачи в Android; при открытом приложении синхронизация работает параллельно со сканированием, а после возобновления работы продолжает.
4. Неопределённые серверные результаты не отправляются повторно. Для них необходима сверка или серверный идемпотентный retry на том же jobId. По умолчанию безопаснее остановить одно задание, чем списать его дважды.
5. Это **клиентское обновление**. В репозитории нет исходника Google Apps Script, поэтому нельзя гарантировать атомарность его записи в Google Sheets. На сервере должен быть независимый контроль по jobId с LockService и безопасной обработкой частичного исполнения.
6. В новой версии успешные задания не удаляются из IndexedDB. Для старых уже отправленных заданий, удалённых предыдущей версией, локальную историю восстановить невозможно; их история хранится на сервере.

## Проверки перед слиянием
- Открыть PWA с сохранённой очередью в тестовом профиле браузера: количество jobId и содержимое очереди не изменяются при загрузке.
- Начать новую сборку во время автоматической отправки: камера/сканер и сохранение черновика работают.
- Отключить интернет посреди отправки: SENDING/UNCERTAIN остаются в базе, отсутствует второй POST.
- Восстановить интернет: проверка старых SENDING/UNCERTAIN идёт через op=jobStatus.
- Два таба: одновременно отправляет только один.
- Проверить 6+ заданий: первая волна максимум 5, затем новая волна.
- Проверить CHZ_CONFLICTS: ERROR не отправляется автоматически повторно, исправление создаёт новую сборку.
- Проверить приёмку: существующий поток receipt.js не должен измениться.
- После установки SW v5.3.0 сверить все черновики и очередь на устройстве.

## Выпуск на все терминалы
Только после пилота слить PR в main и дождаться публикации GitHub Pages. ТСД получают новые файлы при загрузке/открытии приложения; активная вкладка не должна автоматически перезагружаться во время сканирования. Для загрузки новой версии достаточно штатного закрытия и нового запуска PWA без очистки данных. Никакой удалённый деплой не способен гарантировать сохранность IndexedDB, если сам пользователь очистит данные сайта, сменит origin или удалит PWA.
