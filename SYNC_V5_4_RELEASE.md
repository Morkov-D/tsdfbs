# StockFlow TSD v5.4.0 — восстановление сессии и офлайн-очереди

## Исправлено
- Первый онлайн-вход с опцией «Запомнить вход на этом ТСД» сохраняет только ID сотрудника и подтверждённую карточку; bearer-токен и PIN не сохраняются.
- Повторный запуск открывает ранее подтверждённый интерфейс, включая офлайн-черновики, без повторного ввода ID, когда пользователь не нажимал «Выйти».
- При подключении к сети и при возврате в PWA приложение получает новый серверный токен через текущий GAS `op=login`. Это возможно, пока backend поддерживает вход только по ID; для защищённой аутентификации потребуется серверный refresh-токен и PIN.
- Менеджер очереди проверяет действующую сессию перед отправкой. При сбое авторизации ждёт и повторяет попытку; IndexedDB не очищает.
- Сборки другого сотрудника не отправляются под текущим токеном.
- В интерфейсе различаются сеть и доступность API.
- Изменён кэш Service Worker с v5.3.0 на v5.4.0, включая auth.js; имена IndexedDB, версия и stores остались без изменений.

## Что не меняется
- `SENDING` и `UNCERTAIN` автоматически перепроверяются по `jobId`, но **не** отправляются вторым POST без определённого статуса. Это защита от двойного списания.
- Нет гарантии выполнения Javascript при полностью закрытом Android PWA.
- Исходный Google Apps Script отсутствует в GitHub-репозитории. Идемпотентность и атомарность списаний на сервере этой клиентской правкой не изменяются.

## Проверка перед выпуском
1. Экспортировать очереди IndexedDB на одном тестовом ТСД. Не удалять приложение и не очищать данные сайта.
2. Войти онлайн с «Запомнить вход», создать тестовую сборку, полностью закрыть и повторно открыть PWA. Проверить вход и сохранность очереди.
3. Отключить сеть, создать две тестовые сборки, открыть приложение снова; вернуть сеть. Проверить TSD_JOBS, MOVEMENTS, BALANCES, CHZ и статусы локальной очереди.
4. Проверить смену сотрудника: старые сборки остаются локально, но не отправляются под другой учётной записью.
5. Проверить `UNCERTAIN`: нет повторного POST; при возвращении серверного SUCCESS статус подтверждается.
6. После пилота слияние в main запустит обычную публикацию GitHub Pages, если она настроена на main.

### Известное ограничение
Для продакшен-безопасности вход только по ID нужно заменить серверной проверкой PIN или другого фактора, токеном устройства с датой истечения, отзывом доступа и ротацией. Это требует изменения Google Apps Script, которого нет в данном репозитории.
